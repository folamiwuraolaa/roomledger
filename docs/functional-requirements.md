# Functional Requirements

| ID | Requirement | Acceptance criterion |
|---|---|---|
| FR-01 | Registration | Valid user account is created. |
| FR-02 | Account flow selection | Visitor can choose the create-household or join-household flow during registration. |
| FR-03 | Invite code | Member can join with a valid admin code. |
| FR-04 | Login/logout | Session starts and ends correctly. |
| FR-05 | Household creation | Admin can create a household and receives a unique code. |
| FR-06 | Expense creation | Member can record shared expenses. |
| FR-07 | Split validation | Shares sum exactly to total. |
| FR-08 | Balance calculation | Net balances match recorded expenses and settlements. |
| FR-09 | Debt view | User can see who owes whom. |
| FR-10 | Settlement | User can record partial/full payment. |
| FR-11 | Settlement protection | Over-settlement and cross-household settlement are rejected. |
| FR-12 | Household administration | Admin can change roles/remove settled members. |
| FR-13 | Receipts | Expense and settlement PDFs can be generated. |
| FR-14 | Notifications | Relevant household members receive in-app notifications. |
| FR-15 | Super Admin setup | First setup succeeds; later setup is disabled. |
| FR-16 | Super Admin overview | System-level statistics and records are visible. |
